# 驗證與交接

## 驗收矩陣

| 等級 | 要看到的證據 | 不能據此聲稱 |
| --- | --- | --- |
| 原始碼／離線 | 使用假資料的正例、缺項、錯誤與停止路徑；編譯或測試結果可重現 | 實際平台、相依、網路或容器可運作 |
| 目標機唯讀預檢 | 實際版本、選定本機服務及指定資源的觀察；逾時與不可見須報未確認 | 工作執行、保留資源或下一次啟動已獲批准 |
| 原機限定實測 | 核准的單次合成工作，回傳、完成／清理、成果讀回可對應同一輪 | 其他機器、任意輸入、常駐或正式營運可用 |
| 乾淨機移植 | 從取得固定工件、配置到獨立跑通及回復，標明有否用預裝依賴或快取 | 超出實測平台、版本或業務範圍的保證 |

選擇與需求相稱的證據，不為了湊表格擴張測試或要求一輪輪批准。機密資料不做為共用測試輸入。

## 常見誤判與最小修正

- **同名映像、模型或版本：** 分開核對來源發行包、所選架構、登錄站 manifest 和實際安裝後的檔案或映像 config。只核對模型名稱、大小或標頭時，回報這個限定；不能稱全檔雜湊通過。大型檔的完整雜湊適合明示選擇，並與短時限的啟動前核對分開。
- **舊機成功、新機沒紀錄：** 新機使用自己的設定及本次產物；證實指定範圍是新的，而且必要路徑、埠及資源可以核對。既有機器用真實、限定範圍的資源清單。兩者分不清楚就標阻擋，不把缺帳冊當安全。
- **退出碼與實物不同步：** 例如寫入模式正確，最後一步卻用錯模式來驗證。不要再寫一次；在原核准範圍內，從新一次唯讀檢查核對實際檔案、內容和權限。若實物確已完整，記錄「寫入回報有誤、獨立讀回已確認」；若未知，保留部分狀態並說明。這不等於驗收工作已啟動。
- **已接單或串流 EOF：** 「接收請求 → 合規輸出 → 正常結束 → 權限撤銷和清理 → 結果讀回」是不同關卡。不要把其中一步升格。只清理以本次程序證據可歸屬的資源；不要用全域 prune、停止共享服務或刪除帳冊來讓測試通過。
- **repo 有資料卻沒有入口：** README 首屏直接寫清要解決的問題、誰能使用、實測支持到哪。將人工盤點變成可執行的預檢，準備固定煙霧測試與對應測試，連結安裝與回復手冊。當缺少可攜啟動資產時，說「預檢可跑，完整驗收被阻擋」，不要把有一支 shell script 稱為可部署。

## 最小交接記錄

每次只保留會影響下一步的資訊：

```text
目標與真實驗收標準：
環境／來源版本與已核對工件：
目前證據等級：
本次已批准範圍與已用掉的一次性操作：
已完成與未完成（含部分效果或不確定狀態）：
最小下一步／阻礙／由誰執行：
交付位置與獨立讀回結果：
```

同一次批准可以涵蓋清楚描述且相關的步驟，但不能把之後的核對或人工確認省略。若只需要手冊或原型，保留這個範圍，不擅自部署、安裝、發布或聯絡他人。
