# 可重現的本機部署與驗收

把「原機有跑通」轉成「別人拿到可跑的入口，能清楚辨識成功和失敗」。不要把報告、提示詞、原機啟動器或模擬測試當成可攜安裝。

## 開工前定義成果

- 接續既有任務先讀最近的可信交接、實測結果和 repo／工件版本。仍適用的證據直接沿用；只重查已變動、過期或無法對上的項目。
- 區分查資料、唯讀盤點、安裝／寫入、真機啟動、對外發布。沿用已核准的範圍，不把階段擴張成一次通用許可。
- 先讀目標版本的官方文件、依賴清單和現有 repo；列出必要的控制、可用資源、回傳格式、預期時間和唯一最小驗收案例。用有代表性的參數，不用已知必然失敗的限制來代替資安控制。
- 確認環境與團隊能執行的交付物。優先做可用的入口與測試，再補 README 或提示詞。獨立的文件、來源查核、單元測試可並行；會爭用同一個模型、連接埠、容器引擎或狀態的實跑要協調。

## 實作與驗證

1. **盤點與執行分開。** 預檢預設唯讀、不安裝、不啟動，提供檢查結果、缺項和退出碼。預檢通過不等於安裝就緒、資安驗收或啟動授權。真正驗收入口在缺少可信套件或人工確認時明確回報阻擋；不得接受任意啟動器或把提示說明當成功。
2. **弄清楚何者可攜。** 固定元件版本、來源、權限、網路與工作邊界；把主機特有的路徑、帳號、引擎與資源作為目標環境的設定。新機須證實指定新範圍可用，不能複製舊主機狀態、憑證、授權或補造歷史帳冊。版本或標籤不證明檔案相同。詳細判定見 [驗證與交接](references/verification-and-handoff.md)。
3. **用程式判斷固定協定。** 用官方契約解析欄位、型別、完成和錯誤，不請模型猜定型輸出；模型只處理必要的語意工作。將提交成功、結果確認、正常停止、資源回收和成果讀回分開記錄。測試可用固定虛構輸入，但不得讀真實專案或對外連線，除非這是已核准的測試範圍。
4. **先查現況，才決定重試。** 錯誤訊息可能在寫入後才產生。對可能已生效的步驟，只在既有授權內獨立讀回指定產物或資源；原因未知就停，不盲目重跑、覆寫或清理。不可把工具超時、EOF、程序已離開或回收成功互相當成替代證據。
5. **交付可接續的證據。** 更新核准的 repo 路徑或交付物；遠端發布後從遠端讀回確認。分開標記離線模擬、原機實測、第二台乾淨環境及正式上線。只報能證明的等級。回報前先接上仍可做的下一步；真的卡在設備、資料、授權或決策才暫停該步。

## 判定與回報

說清楚「可直接執行哪個入口」「哪些測試通過」「哪些條件還阻擋」和下一個可驗收結果。若需要交接或診斷未確認的結果，讀 [驗證與交接](references/verification-and-handoff.md)。保留最小可續作紀錄，不放密鑰、原始個人資料、私有主機路徑或外部發布不需的日誌。
