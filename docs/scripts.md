# 本機預檢與虛構驗收入口

這兩個入口只處理 OpenClaw 的本機試行。沒有一鍵安裝、雲端模型回退或對外服務。

## 1. 先做唯讀預檢

```sh
bash scripts/preflight.sh
```

預檢不安裝、不下載、不啟動容器或模型。它區分已通過、缺資料、環境不符合和無法確認。需要提供目標機的本機資源時，先用 `bash scripts/preflight.sh --help` 看支援的參數，不要把第一台 Mac 的私有路徑、帳冊或憑證貼到另一台。

## 2. 確認驗收入口

```sh
bash scripts/run-smoke-test.sh
```

目前 repo **未附可移植的新機封存、經核准的啟動程式和依賴套件**。所以入口會以非零狀態回報阻擋，**不會啟動工作，也不會回報驗收成功**。預檢通過也不能當作啟動授權。不要用舊機指令、任意指令或改變權限來繞過這個關卡。

日後的實機驗收必須由目標 Mac 本人確認，只跑一筆固定虛構資料；確認前重新核對同輪資源，成功時才寫入並讀回一份新結果。失敗不自動重跑。

## 預檢退出碼

| 退出碼 | 意義 |
| --- | --- |
| 0 | 此次實際列出的盤點項目通過；不是安裝就緒、資安驗收或啟動授權 |
| 1 | 明確不支援或檢查不符 |
| 2 | 資料不足、檢查無法確認或參數有誤 |

輸出預設是 JSON。沒有指定本機資源就不猜測、也不掃描它們。模型全檔約 24 GB；只有明確使用 `--full-model-hash` 才讀取全部權重。檔案大小和 GGUF 標頭吻合不等於全檔比對通過。

驗收入口目前退出碼為 3（`portable_runtime_unavailable`，未啟動）。`--help` 的退出碼 0 只代表說明正常顯示。

進階盤點需要自行提供已獨立驗證的安裝檔與雜湊；`--help` 列出完整欄位。Pins 檔中的 `image_id` 是本機快取映像的 config ID（Docker 顯示的 `.Id`），不是登錄站的 manifest digest。不要把純版本相同或下載壓縮檔的雜湊當成已安裝檔案的雜湊。只有指定本機 Unix socket、嚴格限定的空白 Docker config 和已驗證 Docker CLI 時，預檢才會檢查那一個已快取映像。連接埠的結果只表示查核當時，不能保留連接埠或充當資安驗收。

## 離線測試

```sh
python3 -I -B -S -m unittest discover -s tests -v
```

測試用受控資料驗證 CLI、雜湊核對、部分檢查不能誤報通過，以及驗收拒絕。Linux 的入口整合測試不碰 Docker 或模型；不代表 macOS 安裝或實機推論。
