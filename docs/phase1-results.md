# Phase 1 結果報告：Mac 本機隔離驗收

**日期：2026-11-23｜判定：一筆固定虛構任務通過。**

在已準備好的 Apple Silicon Mac 上，操作者本人於終端機確認一次執行。最終回報：

```json
{"status":"published","do_not_retry":true}
```

`published` 不只是接單或模型有回應：該版本只有在同次結果驗證、臨時權限撤銷、資源清理確認與成果寫入讀回後才回報發布。終端機畫面是本次實機結案證據；沒有把該畫面當成另一份事後獨立檔案查核或網路封包紀錄。

## 實測範圍

兩個隔離本機容器分別運行 OpenClaw Gateway 與 Claude Agent ACP。本機控制程式負責限定任務及橋接；模型以 Mac 原生 llama-server 執行 Qwen，不靠 Claude 雲端推論或雲端回退。測試只處理一份固定虛構來源，不給模型一般工具權限，不讀取真實專案。模型選擇允許的引用與順序；主持程式獨立採用固定事實，符合規則才產生核對卡，不自行把不合規回覆改成成功。

| 階段 | 結果 | 證據限制 |
|---|---|---|
| 先前一輪資源清點 | 指定容器（含停止）、程序、暫存和埠的當下唯讀核對通過 | 不是後續的資源空閒保證 |
| Mac 啟動前預演 | 正常子程序可回收；雙管線已關閉但程序仍在跑時，必須逾時拒絕並回收；四筆舊範圍核對兩輪，各少於 20 秒 | 無正式工作；同次預演總上限 115 秒，未輸出逐項實測耗時 |
| 放置與獨立讀回 | 48 件資產、封存清單及外部啟動檔的內容與權限均通過 | 初次放置誤報來自寫成 0400、末段驗成 0600。只做獨立讀回，沒有重跑或覆寫 |
| 本人正式單次試行 | 原 Mac 的終端機呈現 `published` | 不可重跑；尚非真實工作、常駐服務、多人或跨機驗收 |
| 離線測試 | 格式、例外、逾時及回收等分別有受控測試 | 不當成另一台 Mac、Linux 安裝或真實推論的證明 |

## 為何修正

- **協議與內容分開判定。** 結束訊號、欄位型別、固定值的判定走程式規則；推論只處理需要它的部分。早期試行出現串流投影欄位或虛構事實不符，本次不以看起來合理的敘述替代證據。
- **結束、撤銷、清理都要確認。** 串流 EOF 不代表子程序已退出，收到回應也不代表臨時身分已撤銷。對應同次工作的證據齊全才允許發布；不明就停止、不自動重試。
- **現場核對不能拿舊結果代替。** 資產先封存、放置後獨立讀回；本人確認後才再核對新鮮資源，並把確認綁到當次任務和成果。

## 待驗與下一步

1. **先完成跨 Mac 可複製性。** 已有[安裝與驗收流程](macos-runbook.md)及設定離線原型，仍需可信的本機資料採集器、目標機封存產生器、固定元件清單與第二台乾淨 Mac 的獨立實測。舊帳冊、身分憑證和原機啟動器不可複製。
2. **補齊工件來源證明。** 原機模型只核對固定大小與 GGUF 標頭，新機要對完整檔案核對可信 SHA-256。官方 ARM64 映像的清單雜湊與本機實測映像的 config ID 是不同項目；取得兩者的權威對照前，不應用同名標籤替代。若證明原機是衍生映像，就補可重建配方及來源。
3. **對外與商業另驗。** 無對外 HTTP 入口、多人隔離、一般資料、任意工具或雲端費用控管的結論。基線沒有額外採用 Octopus、LiteLLM、Magpie 或 WAF；只有需要多模型路由或對外介面時才另立案例。原機試行不代表組件授權或商業成本已解決。
